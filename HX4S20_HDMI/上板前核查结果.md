## PLL 的真实配置与连接

| PLL 输出 | 实际频率 | 相位 | 用途与连接 |
| --- | --- | --- | --- |
| sys_pll C0 | 100 MHz | 0° | TF/SPI 控制逻辑、写 FIFO 一侧 |
| sys_pll C1 | 125 MHz | 0° | 帧缓存调度及 SDRAM 控制器 |
| sys_pll C2 | 125 MHz | 180° | SDRAM 移相时钟；相差 4 ns |
| video_pll C0 | 25 MHz | 0° | 视频时序、HDMI 编码、音频接收与 ACR |
| video_pll C1 | 125 MHz | 0° | HDMI 5 倍串行时钟，ODDR 双沿输出 |
| PLL_HDMI_AUDIO C2 | 12.295082 MHz | 0° | 内部测试音串行发生器 |

音频 PLL 的 C0 75 MHz 作为反馈参考，C1 375 MHz 未被业务逻辑使用。音频采样率实际约为 48027.66 Hz（主时钟 / 256），相对 48 kHz 约偏高 576 ppm。视频 800×525 总时序配合 25 MHz 得到约 59.52 Hz 刷新率，不是精确的 25.175 MHz 标准像素时钟。没有为掩盖违例修改 SDRAM 相位或加入全局 false path。

此次已把系统和视频 PLL 的 extlock 引出，三个 PLL 的锁定状态共同控制复位；各业务域异步置位复位，等待本域 16 个时钟沿后同步释放。各时钟域之间的其余 CDC 并未因此自动完成签核。

## 数据链路与修复

图片链路为 TF SPI → 扇区扫描/BMP 解析 → 异步 FIFO → SDRAM 双缓冲 → 读 FIFO → RGB/AXIS → HDMI 核 → ODDR/LVDS33 → HDMI A。音频链路为内部音阶发生器 → 串行收发 → HDMI 音频包与 ACR → 同一 HDMI A。**没有 TF 音频文件播放器，不能通过放入 MP3/WAV 实现播放。**

修复内容：

- 视频首像素计数错误导致第 640 个像素没有 TLAST；现已修正。
- 系统/视频 PLL 锁定未参与复位；现已引出并与音频锁定共同控制复位。
- I2S 接收器此前未使用复位；现已补齐同步、移位和输出寄存器复位。
- 视频时序二级延迟寄存器补复位。
- FIFO IP 实际输出为 9 位占用计数，向 10 位控制接口显式补零；顶层帧地址与长度位宽统一。
