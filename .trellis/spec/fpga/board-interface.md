# 板卡与存储契约

## 范围与接口

适用于 HX4S20 HDL2410 板卡适配、TF 图片准备和按键验收。顶层接口见 board/hx4s20_board_top.v，管脚来源 constraints/hx4s20_hdmi_a.adc。

|板上标签/接口|顶层信号/位置|行为|
|---|---|---|
|KEY1|rst_n / A2|低有效复位，重新扫描首图|
|KEY2|key1 / B2|手动下一张|
|KEY3|key2 / B1|自动轮播开关|
|TF SPI|CS A12、CLK A14、MOSI A13、MISO B14|原始扇区读取|
|HDMI A|CLK K1、D0 F5、D1 E3、D2 B3|LVDS33；负端 J1/F4/E4/D3|
|DDC|P1/R1|依 ADC 配置|

## 数据合同

SD/bmp_read.v 不解析 FAT 文件名，在前 131072 个物理扇区内查找 BM 头。准备 640×480、24 位、无压缩、正高度 BMP，保持像素数据物理连续；常规 54 字节头每张 921654 字节。001.bmp～004.bmp 只是方便人工管理，读取顺序按物理位置，不由名称决定。不支持 JPG/PNG，也没有 MP3/WAV 播放器。

数码管位选高有效、段选低有效，SW6 上拨。真实适配：

```verilog
assign seg_sel = {~app_seg_sel_n, 2'b00};
```

top_tf_hdmi_audio.v 只给 seg_data_5 接 state_code，其余五个数据端空白，适配层关闭另外两位。预期只有一个状态数字，不把用户所述多位同时亮直接视为通过。

## 校验与错误矩阵

|情况|判断/后续|
|---|---|
|四张标准 BMP，连续且在扫描范围内|具备当前读取条件，仍需卡片及整机验证|
|BMP 正确但碎片化或超出前 64 MiB|可能读不到/花屏，重新检查实际物理布局|
|放入 JPG、PNG、MP3、WAV|不支持该输入，改名无效|
|KEY2 按下短暂状态 2 后回 1|扫描/加载后空闲，不代表图片编号|
|多位同时显示同一数字|记录实测，核查位选、扫描串扰和烧录版本|

## 好/基本/坏案例与测试

好：标准 BMP 并已核查卡上的扇区连续性；基本：仅本机 BMP 解码回归通过，还不能说明卡布局；坏：只按名称排序，假定 FAT 会被解析。board/tests/tb_bmp.v 校验每张 307200 个 RGB 像素，但模拟扇区输入，不验证实际 SPI 电气或卡初始化。引脚检查用 python board/verify_pin_report.py。正确做法是分别记录模拟、卡布局和实板证据，不能互相替代。
