# 任务02：SDRAM 时序最优方案研究

日期：2026-10-16

## 结论

在当前 TD 6.2.168116、`EG_PHY_SDRAM_2M_32` 封装、加密控制器和现有约束下，已经用独立构建验证的最高可接受方案是 **C1/C2=41.666667 MHz，C2 相对 C1 为 180°**。正式构建的全局 SWNS 为 **+0.133 ns**，STNS 为 0，HWNS 为 +0.003 ns，位流已生成。

这不是 EG4S20 器件的最高工作频率。安路 EG4S20 数据手册给出的片上 SDR SDRAM 最高规格为 200 MHz；当前降频是为了满足这份工程中硬核 DQ、PAD 采样寄存器、移相时钟和现有约束共同形成的时序路径。参考：[EG4S20 数据手册 V1.4](https://dl.sipeed.com/TANG/Premier/HDK/Datasheet/EG4S20_DataSheet_V1.4.pdf)。

## 为什么 125 MHz 不能直接保留

125 MHz 的最差路径是片上 SDRAM 硬核 DQ 到 `EG_PHY_PAD` 输入采样点，路径逻辑级数为 0，但硬核输出延迟、PAD 内部采样、局部时钟/数据布线和 180°半周期共同消耗了预算。原报告中该路径数据延迟为 6.453 ns，而有效预算只有 4 ns，因此单纯改成 `TimingUltra` 没有改善；给 C2 单独插入全局缓冲还使结果略差。

读数据 `clk` 未驱动消息也不能通过给加密核寄存器强行接时钟来处理。网表追踪表明，真正使用的 32 个输入采样寄存器已经并入 `EG_PHY_PAD`，其 `ipclk` 连接到 `u1_init_ref/Sdr_clk`；日志中的 `Sdr_rd_dout_reg[*]` 是被 keep 保留、没有输出的旧残留单元，最终合法化网表中已清除。工程保留原加密核主体和原包装层。

## 对功能速度的影响

SDRAM 数据宽度为 32 bit，41.667 MHz 下理论字吞吐约 41.667 Mword/s；当前 640×480、逐像素一字的 HDMI 有效区平均约 18.286 Mword/s，因此从平均带宽看有余量。TF SPI 仍为 25 MHz，图片装载速度主要受 TF 和突发写入影响。刷新计数、初始化等待和帧缓存交互的实际长稳效果必须用新位流在 HX42S20 板上验证，不能只用仿真推断。

## 真正提高到 50/125 MHz 的最优路线

如果后续目标是恢复更高 SDRAM 频率，优先级应为：

1. 向安路确认当前 TD/IP 版本对应的 `EG_PHY_SDRAM_2M_32` SIP 时序约束、输入/输出延迟补偿和推荐 PLL 相位配置，或获取更新的 IP/器件模型。
2. 在明确的 SIP 约束接口下验证 `INDEL/OUTDEL` 或官方推荐的专用时钟补偿；不能凭经验给普通 IO 加延迟，也不能用 false path 绕过真实 DQ 采样路径。
3. 补全 SDC 的生成时钟、SDRAM 输入输出关系和 CDC 约束，再分别签核 50 MHz、62.5 MHz、125 MHz，并保留慢角/快角报告。
4. 每个频率都要重新跑 TF 扫描、SDRAM 读写、HDMI 四图、按键切图、自动轮播和长稳实板测试。

在拿到厂商推荐的 SIP 时序约束前，41.667 MHz 是当前证据最充分的工程选择；不能把“器件规格允许 200 MHz”直接等同于这份加密控制器和当前约束能够在 125 MHz 收敛。

## 当前限制

- 原始综合日志仍会显示加密核残留单元的未驱动 `clk` 消息；最终物理网表核查已证明有效采样寄存器有时钟，但工具日志文字本身没有被修改。
- 当前 SDC 仍是输入 50 MHz 基础时钟和 `derive_clocks`，完整的 IO/CDC 签核以及板级时钟测量尚未完成。
- 新 41.667 MHz 位流尚未由用户完成冷启动、TF 全量扫描、四图切换、自动轮播、音频和长时间运行验收。
