# 官方例程上板现象对照

记录日期：2026-10-15。任务 01 为“验证官方例程”；以下代码预期用来对照实测，不能当作已经完成的全部实测结果。

## 准备条件

使用对应 HX4S20 HDL2410 手册的板卡、当前工程位流、准备好的 TF 卡及 HDMI A。SW6 上拨后数码管模块可显示。卡中图片为 640×480、24 位、无压缩、正高度 BMP，物理数据连续并位于前 64 MiB 扫描范围内。001.bmp～004.bmp 是管理文件名，硬件按物理扇区查找图像。

## 正常操作对照

|操作|正常预期|本次用户反馈/待确认|
|---|---|---|
|上电、等待 PLL 锁定与卡初始化|扫描图片，加载首张后稳定显示；等待时间取决于扫描位置|用户描述上电后状态 1，整体大体正常；首图具体内容及等待时间未精确记录|
|SW6 上拨|启用数码管显示，静止显示图像时状态通常为 1|用户描述“数码管0～6位显示1”，多位同时显示的含义待确认|
|按下并松开板上 KEY1|复位并重新扫描，回到第一张图片；扫描/加载时可能看到 2，完成后回 1|用户报告看到 2，之后画面回到第一张，符合复位重扫方向|
|短按板上 KEY2|切换下一张已发现的图片，加载完成后状态回 1；遍历后回到首张|用户报告下一张及状态跳到 2；最终是否回 1、四张完整顺序待补记|
|短按板上 KEY3|开启自动轮播，再按一次关闭；约 1 秒空闲计时加加载时间，因此并非严格每秒切图|用户报告可自动轮播；关闭动作及持续时长待补记|
|观察静止图片|图像稳定，色彩和方向正确，无花屏、撕裂、异常黑屏|用户笼统判断大体正常，未逐项给出持续观察结果|
|HDMI 音频|当前代码应输出内部生成的音阶测试音；显示器需支持音频并开启音量|用户尚未明确报告声音结果；卡上的 MP3/WAV 不会被读取|

板上 KEY1/KEY2/KEY3 对应 RTL 的 rst_n/key1/key2，不能根据源码 key1 名字误认为板上 KEY1 是下一张。

## 数码管状态含义

来自 SD/bmp_read.v 的 state_code，是运行状态而非图片编号。

|状态|含义|
|---|---|
|0|复位或 TF 尚未初始化完成|
|1|空闲/加载完成，可保持当前画面|
|2|扫描 BMP 或加载图片头|
|3|等待写请求应答|
|4|搬运图像数据|

3、4 往往持续很短，肉眼未见不代表故障。2 可以停留较久，但不能据此判断当前显示第 2 张。

源码仅将一个扫描位置接到状态码，其余位置为空白，并在板级关闭另外两位，预期只有一个状态数字。如果实测确实是 0～6 多个位置同时显示相同数字，应另行检查数码管位选极性、扫描串扰及实际烧录版本，当前仅保留此反馈，未将其判定为正常。

## 本次实板结论与后续复核

用户实板初测表明显示及主要按键功能大体可用，可以作为后续优化的功能基线。尚无实际烧录文件哈希、音频确认、完整四图顺序、重复冷启动、长时间稳定性或精确数码管观察记录。

历史 SDRAM STA 仍为 SWNS -6.699 ns，初测显示正常不代表时序问题消失。后续优化时逐项补充：记录烧录文件与哈希；依次检查四图及首尾回环；验证轮播开启/关闭；反复复位和冷启动；检查音频及长时间运行；核对数码管亮的具体位置。此处是对照清单，未填写的项目均不记为已通过。
